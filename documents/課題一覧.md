## A. 動作不良につながるもの

### A-1. 一時ファイルのパスが引用符で囲まれていない（優先度：高）
- **対象**：`src/extension.ts:141`
- **現状**：
  ```typescript
  terminal.sendText(jshellCommand + ' ' + '-J-Dfile.encoding=utf8 --execution local' + ' ' + temp_jshell_file + ' && exit');
  ```
  `jshellCommand` は Windows のとき二重引用符で囲まれるが（136行）、`temp_jshell_file` は**囲まれていない**。
- **問題**：一時ディレクトリのパスに空白が含まれる場合、引数が分割されて JShell がファイルを読めない。
  Windows では `C:\Users\<ユーザー名>\AppData\Local\Temp` がユーザー名に空白を含むケースがあり、実際に踏みやすい。
- **対処案**：`'"' + temp_jshell_file + '"'` のように囲む。

### A-2. 全角スペースの置換が文字列リテラルにも及ぶ（優先度：中）
- **対象**：`src/extension.ts:79, 90`
- **現状**：`.replace(/\u3000/g, ' ')` を**コード全体**に適用している。
- **問題**：コメント中の全角スペースを除去する目的（コミット `15c31a5`）だが、
  `System.out.println("氏名　太郎")` のような**文字列リテラル内の全角スペースも半角へ変わる**。実行結果が元コードと変わる。
- **対処案**：文字列リテラルを除外する、または JShell 側のパーサが許容する範囲を確認したうえで対象を絞る。

### A-3. `checkJavaClassWithMain` のクラス本体抽出が最初の `}` で終わる（優先度：中）
- **対象**：`src/extension.ts:171`
- **現状**：`/\bpublic\s+class\s+(\w+)\s*\{([\s\S]*?)\}/g`（非貪欲マッチ）
- **問題**：クラス本体を**最初に現れる `}` まで**しか取得しないため、
  main メソッドの前にメソッドやブロックがあると main を検出できず、`<クラス名>.main(...)` が追記されない。
  結果として、ファイル全体を実行してもクラス定義が登録されるだけで何も実行されない。
- **あわせて**：`public class` のみが対象。`class`（パッケージプライベート）や `final class` は検出できない。

### A-4. `chmod` の完了を待たずに実行へ進む（優先度：低）
- **対象**：`src/extension.ts:128, 154-166`
- **現状**：`chmodFolder()` 内で `fsex.chmod()`（非同期）を呼び出しているが、完了を待っていない。
- **問題**：同梱JREの初回コピー直後に JShell を起動すると、権限付与が完了しておらず実行に失敗する可能性がある。
  ※現状 `jre_linux` が同梱されていない（B-1）ため、この経路は Windows では通らず、顕在化していない。
- **対処案**：`fsex.chmodSync()` を使う、または `await` する。

## B. 環境・プラットフォーム

### B-1. Windows 以外では同梱 Java が使えない（優先度：高）
- **対象**：`src/extension.ts:116, 127` ／ `dist/`
- **現状**：Windows 以外では `jre_linux` を参照するが、**`dist/jre_linux` は存在しない**（`dist/` にあるのは `jre_win` のみ）。
- **問題**：Linux / macOS で `java_home` を設定せずに実行すると、`fsex.copySync` が例外を投げる。
  例外は捕捉されていないため、利用者には原因が分からないまま失敗する。
- **対処案**：`jre_linux` を同梱する、または未同梱時は「java_home の設定が必要」と明示するエラーを出す。
- **あわせて**：README に「Windows 以外では java_home の設定が必要」という記載が無い。

### B-2. 入力の文字コードが `MS932` 固定（優先度：中）
- **対象**：`src/extension.ts:38, 97`
- **現状**：`new Scanner(System.in, "MS932")` と固定。一方で JShell 起動時は `-J-Dfile.encoding=utf8` を指定している。
- **問題**：UTF-8 環境（Linux / macOS、および UTF-8 に設定した Windows ターミナル）では、日本語入力が文字化けする可能性がある。
  出力は UTF-8、入力は MS932 と前提が食い違っている。
- **対処案**：入力も UTF-8 に揃える、または設定で切り替えられるようにする。

## D. 保守性・設計

### D-1. コマンドの表示条件が機能していない（未対応）
- **対象**：`package.json` の `contributes.commands`
- **意図**：VS Code で開いているテキストの言語が Java のときだけ、このコマンドを使えるようにする。
- **現状**：
  ```json
  { "when": "resourceLangId == Java", "command": "JavaCodeSelectionRunner.RunCode", "title": "Run JavaCode" }
  ```
- **問題**：意図どおりに効いていない。理由は2点。
  1. `contributes.commands` の項目で有効・無効を切り替える属性は **`enablement`** であり、`when` は `contributes.menus` 側で使う。
     このため `when` の指定は無視される。
  2. 値が `Java`（大文字始まり）だが、`contributes.languages` で定義している言語IDは **`java`（小文字）**。
     `resourceLangId` は言語IDと比較するため、この条件はそもそも成立しない。
- **現状の影響**：右クリックメニューの項目（`contributes.menus.editor/context`）にも `when` が無いため、
  **Java 以外のファイルでもメニューに「Run JavaCode」が表示される**。
  実行した場合は `src/extension.ts:26` の判定で `This is not a Java file.` と表示されるため実害は無いが、意図とは異なる。
- **対処案**：条件をメニュー側に付ける。コマンドパレットからの実行も塞ぐ場合は `enablement` も併記する。
  ```json
  "commands": [
    { "command": "JavaCodeSelectionRunner.RunCode", "title": "Run JavaCode", "enablement": "resourceLangId == java" }
  ],
  "menus": {
    "editor/context": [
      { "command": "JavaCodeSelectionRunner.RunCode", "when": "resourceLangId == java", "group": "myGroup@1" }
    ]
  }
  ```
- **備考**：実際の挙動は拡張機能を導入して検証予定（2026-09-18 時点）。

### D-2. 一時ファイルが削除されない（未対応）
- **対象**：`src/extension.ts:102-105`
- 実行のたびに `os.tmpdir()` へ `vscode-extension-temp<乱数8桁>.jsh` が作られるが、削除処理が無い。
- OS の一時ディレクトリなので最終的には掃除されるが、実行のたびに増える。

### D-3. `fs.writeFile` のエラーを検査していない（未対応）
- **対象**：`src/extension.ts:105`
- コールバックの引数 `err` を受け取っているが検査していないため、書き出しに失敗しても処理が進み、
  存在しないファイルを JShell に渡すことになる。

### D-4. `iconv-lite` が依存関係に含まれるが使用されていない（未対応）
- **対象**：`package.json` の `dependencies`
- `src/extension.ts` および `dist/extension.js` に `iconv` の参照が無い。過去の実装の名残と思われる。

### D-5. ビルド成果物と同梱JREがリポジトリにコミットされている（要検討）
- **対象**：`dist/`（162ファイルが Git 管理下。うち大半が `jre_win` のバイナリ）
- `.gitignore` は `node_modules` と `.vsix` のみを除外しており、`dist/` は管理対象。
- VSIX のパッケージに JRE を含める必要があるため同梱自体は妥当だが、
  バイナリを Git で持つとリポジトリが肥大化する。リリース時に取得する方式なども検討余地がある。
