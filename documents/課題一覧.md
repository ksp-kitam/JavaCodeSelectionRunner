## A. 動作不良につながるもの

### A-1. 一時ファイルのパスが引用符で囲まれていない　→ **対応済み**
- **以前**：`jshellCommand` は Windows のとき二重引用符で囲まれていたが、`.jsh` のパスは囲まれていなかった。
  一時ディレクトリのパスに空白が含まれると引数が分割され、JShell がファイルを読めなかった。
- **対応**：`quotePath()` を追加し、**JShell のパスと一時ファイルのパスの両方**を二重引用符で囲むようにした。
  Windows 限定だった引用符付与を全プラットフォームへ統一している。

### A-2. 全角スペースの置換が文字列リテラルにも及ぶ　→ **対応済み**
- **以前**：`.replace(/　/g, ' ')` をコード全体に適用していたため、
  `System.out.println("氏名　太郎")` のような**文字列リテラル内の全角スペースも半角へ変わっていた**。
- **対応**：`replaceFullWidthSpace()` を新設し、1文字ずつ文脈を判定して置換するようにした。
  - 置換する：コード部分、行コメント、ブロックコメント
  - 置換しない：文字列リテラル、文字リテラル、テキストブロック（`"""`）
  - リテラル内のエスケープ（`\"` など）も正しく扱う

### A-3. `checkJavaClassWithMain` のクラス本体抽出が最初の `}` で終わる　→ **対応済み**
- **以前**：`/\bpublic\s+class\s+(\w+)\s*\{([\s\S]*?)\}/g`（非貪欲マッチ）でクラス本体を**最初の `}` まで**しか取得しておらず、
  main メソッドの前に別のメソッドやブロックがあると検出できなかった。`public class` 以外も対象外だった。
- **対応**：
  - `maskLiteralsAndComments()` でリテラル・コメントを除いたうえで、**波括弧の対応を数えて**クラス本体を特定する方式へ変更。
  - クラス抽出の正規表現を `/\bclass\s+(\w+)/g` とし、`public` 以外の修飾子にも対応。
  - main の判定を `String[] args` / `String args[]` / `final String[] args` に対応。

### A-4. `chmod` の完了を待たずに実行へ進む　→ **対応済み**
- **以前**：`fs-extra` の非同期 `chmod()` を待たずに JShell を起動していた。
- **対応**：`fs.chmodSync()`（同期）へ変更し、権限付与の完了後に実行へ進むようにした。

## B. 環境・プラットフォーム

### B-1. Windows 以外では同梱 Java が使えない　→ **対応済み（案B：明示して中断する方式）**
- **以前**：Windows 以外では存在しない `dist/jre_linux` をコピーしようとして例外が発生し、
  捕捉もされていなかったため利用者に原因が分からなかった。
- **対応**：
  - 同梱JREの有無を事前に確認し、無い場合は
    `Java for this platform is not bundled. Please set "JavaCodeSelectionRunner.java_home" in the settings.`
    を表示して中断するようにした。
  - コピー処理を `try/catch` で囲み、失敗時は `Failed to prepare the bundled Java.` を表示するようにした。
  - README（日本語・英語）に「同梱JavaはWindows用のみ。Windows以外では java_home の設定が必須」と明記した。
- **備考**：Linux 用 JRE の同梱は行わない方針（リポジトリ・VSIX の肥大化を避けるため）。

### B-2. 入力の文字コードが `MS932` 固定　→ **対応済み（案B：OSで切り替え）**
- **以前**：`new Scanner(System.in, "MS932")` が固定で、UTF-8 環境では日本語入力が文字化けする可能性があった。
- **対応**：`inputCharset` を導入し、**Windows は `MS932`、それ以外は `UTF-8`** を使うようにした。
  既存の Windows 環境の挙動は変えずに、他OSへ対応している。

## D. 保守性・設計

### D-1. コマンドの表示条件が機能していない　→ **対応済み**
- **意図**：開いているテキストの言語が Java のときだけコマンドを使えるようにする。
- **以前**：`contributes.commands` に `"when": "resourceLangId == Java"` と記載していたが、
  1. コマンド定義側で有効・無効を切り替える属性は `enablement` であり `when` は無視される
  2. 値が `Java`（大文字始まり）で、言語ID `java`（小文字）と一致しない
  という2点により機能しておらず、Java 以外のファイルでも右クリックメニューに表示されていた。
- **対応**：
  ```json
  "commands": [
    { "command": "JavaCodeSelectionRunner.RunCode", "title": "Run JavaCode", "enablement": "resourceLangId == java" }
  ],
  "menus": {
    "editor/context": [
      { "command": "JavaCodeSelectionRunner.RunCode", "when": "resourceLangId == java", "group": "myGroup@1" }
    ]
  }
  ```
- **備考**：実際の表示挙動は拡張機能を導入して検証予定。

### D-2. 一時ファイルが削除されない　→ **対応済み（案A：起動時に掃除）**
- **以前**：実行のたびに `os.tmpdir()` へ `.jsh` が作られ、削除されなかった。
- **対応**：`cleanUpTempFiles()` を追加し、`activate()` の冒頭で
  接頭辞 `vscode-extension-temp` かつ拡張子 `.jsh` の**24時間以上前のファイル**を削除するようにした。
  ターミナルでの実行は非同期のため実行直後には削除できないことから、起動時の掃除方式を採用している。

### D-3. `fs.writeFile` のエラーを検査していない　→ **対応済み**
- **対応**：コールバックの `err` を検査し、失敗時は
  `Failed to create a temporary file. : <理由>` を表示して以降の処理を行わないようにした。

### D-4. `iconv-lite` が依存関係に含まれるが使用されていない　→ **対応済み**
- **対応**：`package.json` の `dependencies` から削除した（`package-lock.json` も更新）。
- あわせて、未使用だった `import * as cp from 'child_process';` も削除した。

### D-5. ビルド成果物と同梱JREがリポジトリにコミットされている　→ **現状維持（案A）**
- `dist/`（同梱JREを含む162ファイル）は引き続き Git 管理下に置く。
- VSIX 作成の手順が単純である利点を優先し、運用を変更しない方針とした。
